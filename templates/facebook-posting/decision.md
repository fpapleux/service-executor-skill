# Accept/reject: Facebook post

Record acceptance only for the exact approved Page identity, supplied caption/image, feed placement and eligible timing, with publication authority, supported actual capability, complete configuration and current request ownership.

Reject missing required business inputs or conflicting/incomplete definitions with the concrete validation reason. Hold task execution for unresolved Page identity, unavailable access/upload capability, unsupported scheduling or required operator login. Promptly invoke the configured rejection/failure/intervention report with the request ID, reason, confirmed effects and required next step.

Validation success is not itself acceptance. Persist the affirmative decision before any task submission. A temporary communication outage alone does not block otherwise accepted, authorized and independently executable work; keep pending communication as required by the generic lifecycle. Missing required reporting configuration remains a validation failure.

Acceptance does not authorize comments, shares, crossposts, Stories, boosts, revised copy, substituted media, additional destinations or account/security changes. Apply final identity/scope checks and current resource ownership again before submission.
