# Scoped verification

The unit command is `python3 -m unittest discover -s tests -v`. It checks retained evidence and artifacts; it does not silently launch agents, call a model or operate a live service.

## Actual offline applications

Detailed synthetic records and immutable snapshots are retained in `evidence/offline-artifacts.tar.gz`. The tests use `evidence_store.py` to extract them into a temporary folder with the standard safe tar data filter. For manual inspection run `python3 tests/evidence_store.py /path/to/empty-folder`. Local expanded copies are ignored by Git; their archive remains versioned.

`test_offline_application.py` and `test_offline_remaining.py` cover all 44 approved scenarios by inspecting executor-created journals, exact inputs, immutable instruction/configuration bindings, native tool-call logs, effects, receipts and preserved history. No saved reviewer pass flag decides these results.

- `offline_fixture.py` prepares concrete Given files and seeded prior histories. It never resets existing cases, invokes an executor, or writes successful result artifacts. The first export fixture in the archive supplies its input template example. To create fresh concrete Givens, run `python3 tests/offline_fixture.py /path/to/new-fixtures`; no successful effects or agent records are created by that command.
- `offline_native.py` is a passive test double. It logs every requested operation, observes existing kernel locks/journal content, returns fixture-defined native responses, and makes only the requested synthetic file effect. It does not validate, accept, lock, retry, report automatically or implement a lifecycle.
- Actual agents read the skill and selected case, acquire live locks, use ordinary file tools and explicitly call the native double. Positive effects include copied export bytes or a synthetic post record; negative cases retain actual blockers and no unauthorized business effects.
- Two independent executor sessions exercised different requests sharing one profile and two sessions seeking the same request. Kernel acquisition/contention/release observations and passive native snapshots are cross-checked against owner journals and actual effects. The loser does not perform business work or modify another request.
- An additional external-dependency application ran while Linux inotify observed the escaped instruction target. Its retained audit contains zero IN_OPEN/IN_ACCESS events during that actual executor interval.
- The original close-out application failed to record release/quiescence. Its artifacts remain unchanged under `offline/REQ-EXEC-004.S1/`. A narrow operator-authored records-guide correction added an explicit close-out record recipe; a fresh independent application under `offline-retest/` then produced completion evidence, remaining-obligation lists and release under ownership. The external-read audit is separately retained under `offline-read-audit/`.

`offline-red.txt`, task evidence and the first-application failure log retain actual failing assertions. Some test defects were corrected: incidental stage labels, error wording, letter case, receipt references and optional audit metadata are not extra product requirements. Concrete Given corrections explicitly distinguish prior confirmed A from pending B; initial observations are preserved rather than rewritten. One profile contender initially checked the newer discovery file instead of its available retained snapshot; its mismatch blocker, supplied snapshot location and subsequent verified continuation are retained without rebinding or history replacement.

The 44 application assertions span the recorded bound versions. The release-record change was tested in a fresh complete application; older instruction snapshots remain available for already-bound applications. `offline-release-binding.json` binds the final runtime content and invalidates the current evidence check if instructions change without an explicit refresh of affected applications. These are scoped offline results, not certification of arbitrary agents or native accounts.

To repeat an application, create a fresh isolated copy of its Given, select the recorded skill/template/configuration, and ask an independent executor to perform the request with the passive native API. Supply no expected answers/test source or prior response. Retain actual calls, kernel observations, immutable before/after identities and records. For resume supply the durable prior history and explicit request ID, not a narrative of the desired continuation. For concurrency use two live sessions and a deliberate pause while the first holds the actual lock. Do not replace the agent with a Python workflow simulation. `watch_instruction_reads.py` is the test-only access observer used around the independent dependency application.

## Other checks and historical evidence

`test_package.py` checks artifact layout, local Markdown-link closure, escaping links/symlinks, immutable content identities and current release binding. Its link walker is a test utility, not a runtime instruction scanner. `test_ownership.py` checks the actual OS lock primitive; `test_offline_native.py` checks that the double creates only explicit effects and supplies no executor decisions.

The earlier 44 baseline/guided written-decision exercises remain as historical interpretation evidence in `test_exercises.py`. They are now bound to their original retained content under `interpreted-package/`, not falsely presented as execution of the current release. Twenty original task groups correctly record pre-existing interpretation behavior; those warning entries remain untouched. The assisted original written close-out response also remains labelled assisted.

The full suite currently has 98 checks: 44 actual-application artifact assertions, 44 historical interpretation-evidence checks, eight package/identity checks, one OS-lock primitive check and one native-double check. No real credentials, live requests, private customer records, native browser/account action or communication service are used. Synthetic state is intentionally retained under test-specific ignore exceptions; real deployment state must stay outside this repository.
